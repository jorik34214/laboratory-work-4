## Керування процесами-транзакціями в базах даних

### 2.1 Теоретичне завдання зі створення історій виконання транзакцій

2.1.1 Історія квазіпаралельного успішного виконання транзакцій (протокол 1-го ступеня блокування)
Протокол 1-го ступеня блокування (Strict 1PL): транзакція повинна утримувати всі свої блокування до завершення (commit/abort).
H(T1, T2, T3) = W1[K], W3[K], R2[M], W1[M], R2[B], W2[M], R3[B], W3[B], C1, C2, C3

2.1.2 Таблиця блокувань 
char* lock_table[] = {
    "K: T1 (X), T3 (waiting)",
    "M: T1 (X), T2 (waiting)",
    "B: T2 (S), T3 (waiting)"
};

2.1.3 Граф очікувань транзакцій 
Очікування:
T3 очікує X-блок на K → T1
T2 очікує X-блок на M → T1
T3 очікує S-блок на B → T2
int wait[3][3] = {
    {0, 0, 0},
    {1, 0, 0},  
    {1, 1, 0}   
};
Висновок: Є цикл T2 → T1, T3 → T1 і T3 → T2 → це Deadlock.

2.1.4 Історія для протоколу 2-го ступеня блокування (2PL)
Протокол 2PL: транзакція може розширювати свої блокування, але не може захоплювати нові після першого звільнення.
H(T1, T2, T3) = W1[K], W1[M], C1, R2[M], R2[B], W2[M], C2, W3[K], R3[B], W3[B], C3

2.1.5 Граф очікування для історії 2PL
Очікування: Немає очікувань, бо T1 завершує першою і звільняє всі блокування перед тим, як інші транзакції потребують ті самі ресурси.
int wait[3][3] = {
    {0, 0, 0},
    {0, 0, 0},
    {0, 0, 0}
};
Висновок: Deadlock відсутній.
